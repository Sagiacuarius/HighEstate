# Design: Agent Autonomy

## Technical Approach

Additive policy layer over the accepted WU14 agent, never editing accepted seams. The interpretation→match→propose pipeline is extended with two deterministic inputs — a seeded keyword knowledge base and a live-catalog price read — and a pure `agent_policy` function turns the validated plan into `AUTO` or `ESCALATE` before persistence. The draft row stays the durable audit spine: the auto path reuses the accepted analyze/decide/finalize command seams and the router's per-action saga dispatch (`agent-draft:{draft_id}:{index}` idempotency keys, one audit + one outbox per action), with the advisor's click replaced by the policy and only for whitelisted effects — under the owner's OD-1 override the whitelist includes calendar writes, and `AUTO_EVENT_CREATION = False` is the kill-switch that re-gates them. Handoff is a first-class intent + action that pauses auto-replies per conversation until a human resumes. The LangChain upgrade is confined inside `OpenCodeGoProvider`: the `ModelProvider` port, the fail-closed `validate_interpretation` boundary, the offline `StubModelProvider` and every deterministic layer are untouched. Mounted as new routes on the existing `build_agent_router` router — `composition_wu8_mvp.py`'s include line stays byte-identical; migration `008` extends the vocabulary.

## Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| **OD-1 (open decision 1): human gate under auto** | Per-draft all-or-nothing verdict from `agent_policy`. AUTO set: `send_reply` (KB- or catalog-grounded only), `register_interest`, `create_follow_up`, `transition_lead` (stage resolved by name in scope), and — **owner decision 2026-09-16 override: calendar writes auto-execute** — `create_event` and `reschedule_event`. ESCALATE set: unresolved ask_question, no-match search, `update_preferences`, `general`, and every `handoff` draft (whose escalation mechanics — flag/pause/follow-up — run automatically; a reply to the lead never does). **`create_event` recommendation overridden: calendar writes are AUTO by default**; the constant now gates-out instead of gates-in — `AUTO_EVENT_CREATION = True` is the auto-on default; flipping it to `False` = one constant + one harness pin restores the human gate as a kill-switch | The owner prioritized a fully-autonomous demo: the one-click showcase is no longer visits. The original gate held because an unattended event commits advisor time (highest blast radius) and the persona guardrail ("no agendás visitas") mirrored it; under the override that persona line is softened for the auto path (see the `agent_persona.py` note in Files and Composition) and the residual booking risk is carried by the overlap-denial + per-action idempotency safety net at dispatch, truthful `execution_result` recording, and the advisor's accepted WU13 cancel + the manual override endpoints. |
| **OD-2 (open decision 2): auto-decision attribution** | Keep `decided_by uuid` human-only (NULL on auto rows — no magic value in a uuid column). Migration `008`: `status` CHECK gains `'auto'`; new `execution_mode text NOT NULL DEFAULT 'human' CHECK (execution_mode IN ('human','agent_policy'))`; new `auto_decision_actor uuid` written with the deterministic sentinel `uuid5(NAMESPACE_URL, "agent-policy")` on policy decisions, plus new `policy_decision text NOT NULL DEFAULT 'escalate' CHECK (policy_decision IN ('auto','escalate'))` set at analyze. DB backstop: `(status='auto') ⇒ decided_by IS NULL`; command layer enforces `execution_mode='agent_policy' ⇔ auto_decision_actor = sentinel` | A second nullable column keeps the human column honest (it stays joinable to `users` in spirit, never holding text), the sentinel is stable/replayable and renders as a label in the UI, and `policy_decision` makes the computed verdict (independent of who executed) queryable for the escalation surface. |
| **OD-3 (open decision 3): auto trigger scope** | Per-conversation mode, not every-inbound: `008` adds `conversations.agent_mode text NOT NULL DEFAULT 'manual' CHECK (agent_mode IN ('manual','auto','paused'))`. `manual` = accepted WU14 behavior; `auto` = policy executes; `paused` = set only by handoff, silences auto replies until the human resumes. The two seeded demo conversations are flipped to `auto` by `mvp_seed_008.sql`; toggle + resume are dev-only routes on the agent router | Zero-click is a demo property, not a tenant-wide law: `manual` default keeps every other conversation (and the re-pointed WU14 harness) on the accepted behavior, and handoff's `paused` state needs a per-conversation home anyway — one column, three honest states. |
| Draft lifecycle | `proposed → approved | auto | rejected`; `approved | auto → executed`; executed/rejected terminal. `DecideAgentDraftCommand` accepts `decision="auto"` (sets status `auto`, `decided_at=now()`, `decided_by=NULL`, `execution_mode='agent_policy'`, `auto_decision_actor=sentinel`); `FinalizeAgentDraftCommand` accepts source status `approved` or `auto`. Both still lock the row and fail closed on any non-`proposed`/non-actionable status (409) | Monotonic, and the auto decision is an atomic row transition exactly like the human one; the audit trail says which happened. |
| Policy consultation | `agent_policy.evaluate(signals, actions)` called inside `ConversationAgent.analyze` after `_derive_actions`; verdict + reason returned in the plan and persisted on the draft (`policy_decision`); the analyze ROUTE consults `conversations.agent_mode` server-side and executes when `auto ∧ auto`. The approve/reject endpoints never consult the policy (human override > policy) | Pure function over validated facts — no I/O, no model text — so it is unit-testable with the stub and deterministic in the harness. |
| Policy signature | `@dataclass(frozen=True) PolicySignals(intent, kb_match, price_resolved, matched_count, slot_found, handoff_requested, complaint, transition_stage_id: str | None)` → `PolicyDecision(verdict: "auto"|"escalate", reason: str, auto_execute_types: frozenset[str], escalation_execute_types: frozenset[str])`. Constants `AUTO_ACTION_TYPES`, `GATED_ACTION_TYPES`, `ESCALATION_MECHANICS = {"handoff_to_human","create_follow_up"}` | "Low confidence" is defined as absent deterministic signals (no KB hit, no price target, no match, gated action present — only reachable with `AUTO_EVENT_CREATION = False`) — the bounded schema carries no numeric confidence and the design deliberately does not add one (keeping stub + model paths identical). |
| Knowledge base | `knowledge_base_articles` (migration `008`): `id, client_account_id (FK, NOT NULL), demo_seed_key UNIQUE, category CHECK IN ('expensas','escritura','garantia','documentos','financiacion','amenities','requisitos','visitas'), question, keywords text[], answer, created_at, updated_at` + `UNIQUE (id, client_account_id)` + index `(client_account_id, category, id)`. Retrieval adapter `postgres_knowledge_base.py` runs the deterministic keyword-overlap SQL below; the first ordered row is the answer; **zero rows ⇒ `kb_match=False` ⇒ escalate, never fabricate. No pgvector, no embeddings, no F5/tsvector** (stemming choices would defeat the harness oracle; array-overlap scoring is oracled by a pure-Python twin) | Same durable/tenant-scoped discipline as 004–007; every read carries the `client_account_id` predicate first, matching the codebase-wide boundary (shared-table cross-tenant read rejected per proposal). |
| Price from catalog | `ask_question` + deterministic price signal: resolve target property (a) criteria filters → existing `search_properties_for_criteria` top match, else (b) **last-discussed fallback = newest interest row**: `SELECT property_id FROM property_interests WHERE client_account_id=%s AND contact_id=%s ORDER BY created_at DESC, id DESC LIMIT 1` — zero new state, because `register_interest` already writes those rows. Then a live read: `SELECT title, price_amount, price_currency, operation_type FROM properties WHERE id=%s AND client_account_id=%s AND status='available'`; no resolvable target ⇒ escalate | Prices are never in static text; editing the property row changes the next answer. Multi-turn memory stays out of scope (LangGraph candidate). |
| Grounded replies only | The auto path may only persist a `send_reply` whose text is KB-article or catalog-field derived (params `{source: "kb_article"|"price_catalog", article_id?/property_id?}`); `reply_text` is never auto-sent | A model-written sentence with no ground truth is exactly what the whitelist exists to stop; under the real provider the grounded text may be tone-composed by the answer chain (below), under the stub it is the curated article/field template. |
| Outbound persistence | New atomic `PersistOutboundReplyCommand` (`CrmCommandBase`, operation `agent.reply`): scoped + not-paused check on the conversation, INSERT `messages (direction='outbound', external_event_id=agent-draft:{draft_id}:{index}, demo_seed_key NULL)`, bump `conversations.updated_at`, one audit + one outbox. **No direction migration: `messages.direction CHECK (direction IN ('inbound','outbound'))` exists since 004** and `CrmMessagesResponse`/`page.tsx` already render per-direction bubbles | Unmarked effect rows stay compatible with the accepted reset + `clear_simulator_effects`; the reply is auditable like any command effect. |
| Handoff | New intent `handoff` (domain `INTENTS`, `agent_drafts` intent CHECK via 008, system prompt, stub keywords "humano"/"asesor"/"reclamo"/"queja"/"decepcionad*") + new action type `handoff_to_human` `{reason: explicit_request|complaint}`. Auto/escalate verdict table (the OD-1 default, unit- and harness-pinned):

| Trigger (validated) | Planned actions | Verdict | Auto-dispatched when mode=auto |
|---|---|---|---|
| FAQ hit (`ask_question` + KB row) | send_reply(kb_article) | AUTO | reply persisted, outbound message |
| Price hit (`ask_question` + catalog target) | send_reply(price_catalog) | AUTO | reply persisted from live fields |
| Search with ≥1 match | register_interest + create_follow_up + send_reply (+transition_lead when qualification signals + stage resolve) | AUTO | all effects |
| Ask/price unresolved, search with no match | create_follow_up | ESCALATE | nothing (draft waits for the advisor) |
| schedule_visit / reschedule | create_event / reschedule_event + create_follow_up | AUTO | event created / rescheduled automatically — the overlap-denial + per-action idempotency is the safety net: a slot taken between analyze and execution records `create_event=denied` truthfully in `execution_result` (no crash — the draft still reaches `executed` with the per-action denial) |
| update_preferences / general | create_follow_up | ESCALATE | nothing |
| Handoff intent (explicit request or complaint signal) | handoff_to_human + create_follow_up | ESCALATE + mechanics | flag + pause + follow-up; **never a reply** |

## Contracts, Invariants, and Flow

Flow: `POST /v1/demo/agent/analyze {body}` → session context + canonical conversation (as today) → **read `conversations.agent_mode`** → `ConversationAgent.analyze` (interpret → validate → KB lookup / price read / search / slot / stage-name resolution → `_derive_actions` → `agent_policy.evaluate`) → `AnalyzeInboundMessageCommand` INSERTs the draft with `policy_decision`. If mode=`auto`: verdict AUTO → `DecideAgentDraftCommand(decision="auto")` → `_dispatch_actions` → `FinalizeAgentDraftCommand` → 200 `{draft(executed), auto_executed:true}`; verdict ESCALATE with handoff intent → dispatch `ESCALATION_MECHANICS` types only (mode→`paused`). Anything else → status-quo `proposed` draft. `approve`/`reject` endpoints unchanged as the manual override (they accept `proposed` drafts regardless of verdict; a draft already `auto`/`executed` fails closed 409). New: `GET /v1/demo/agent/state`, `POST /v1/demo/agent/state {mode: manual|auto}` (dev-only, never sets `paused`), `POST /v1/demo/agent/handoff/resume`.

Draft response shape gains `"policy_decision" ∈ {auto,escalate}` and `"execution_mode" ∈ {human,agent_policy}` (both strict-enums in the parser); the command response gains `"auto_executed": boolean`. `AgentStateResponse = {contract_version, environment:"dev-only-agent", conversation_id, agent_mode, handoff_open, account_id, correlation_id}`.

Invariants: every read/write carries server-derived `client_account_id`; draft status monotonic (`proposed → approved|auto|rejected`, `approved|auto → executed`); `execution_mode='agent_policy'` ⇒ `decided_by IS NULL` and `auto_decision_actor` = sentinel; `agent_mode` transitions legal: `manual↔auto` (dev surface), `auto→paused` (handoff command only), `paused→auto|manual` (resume); an inbound message on a `paused` conversation produces at most another escalated draft — never a reply; interpretation schema-validated before persistence; policy never sees raw model text; cross-account ids non-enumerating.

SQL shape (KB scoring — deterministic, single statement, account predicate first, parameters only):
```sql
WITH scored AS (
  SELECT a.id, a.category, a.question, a.answer,
         cardinality((SELECT unnest(a.keywords) INTERSECT SELECT unnest(%s::text[]))) AS hits
  FROM knowledge_base_articles a
  WHERE a.client_account_id = %s
)
SELECT id, category, question, answer FROM scored
WHERE hits > 0
ORDER BY hits DESC, category, id
LIMIT 1
```
(tokens = pure-Python normalize: lowercase, accent-strip, non-letter split, fixed stopword set; tie-break total via `(hits, category, id)`). Stage-name resolution (transition target, never guessed): `SELECT s.id FROM pipeline_stages s JOIN leads l ON l.pipeline_id = s.pipeline_id AND l.client_account_id = s.client_account_id WHERE s.client_account_id = %s AND l.id = %s AND s.name = %s`.

Migration `008_agent_autonomy` (next free number after 007; down-file convention mirrors 005/006/007 — a real DROP/restore script even though the runner only executes `--down 004`): UP = (1) `CREATE TABLE knowledge_base_articles` as decided above; (2) `ALTER TABLE agent_drafts DROP CONSTRAINT agent_drafts_intent_check` + re-add with `+'handoff'`; `DROP CONSTRAINT agent_drafts_status_check` + re-add with `+'auto'`; `ADD COLUMN policy_decision`/`execution_mode`/`auto_decision_actor` with the CHECKs; (3) `ALTER TABLE conversations ADD COLUMN agent_mode text NOT NULL DEFAULT 'manual' CHECK (agent_mode IN ('manual','auto','paused'))` (conversations has no pause/auto column today — verified against 004). DOWN reverses each exactly; precondition documented: demo bases are disposable and reset first, since CHECK rollback assumes no `auto`-status / `handoff`-intent rows. Seed: `infra/migrations/validation/mvp_seed_008.sql` mirroring the accepted `mvp_seed_005.sql` layout (`\set ON_ERROR_STOP on`, single transaction, `pg_advisory_xact_lock(hashtext('mvp-commercial-demo-seed-reset'))`, fail-closed ownership gate over `(table, id, account, marker)` VALUES, DELETE-then-INSERT only of owned markers): 16 curated articles per demo account (2 per category across the 8 brief categories; markers `demo-a-kb-001..016`, `demo-b-kb-001..016`) + `UPDATE conversations SET agent_mode='auto'` scoped to the two marker-owned demo conversations.

## Risks and Rollback

Policy turns model/keyword misses into real effects — mitigated by the narrow whitelist (grounded replies only), all-or-nothing per-draft verdict, the schema gate upstream of the policy, and per-conversation `paused`/`manual` as the kill switch. Auto calendar writes — the one contested boundary — the owner resolved (2026-09-16) to AUTO-inclusive, with `AUTO_EVENT_CREATION = False` as the kill-switch to re-gate; the residual risk (a wrong booking writes advisor time) is mitigated by the honest overlap-denial recorded in `execution_result` + the advisor's accepted WU13 cancel and the manual override endpoints. Attribution drift (a human decision labeled policy or vice versa) — closed by the DB CHECK pair + `decided_by IS NULL` invariant + sentinel column, harness-pinned. Keyword retrieval misses paraphrases — a miss is escalate by design, never fabricate; the seed corpus + oracle harness pin expected hits. `agent_mode` races between handoff-pause and a concurrent analyze — the mode write is inside the locked command transaction and the reply command re-checks `paused` at INSERT time (fails closed). LangChain dependency surface — pinned, confined to one class, lazy-imported, stub proven import-free in CI. Rollback: delete the WU15 modules/UI/contract slice, revert the seed-list line and the analyze/dispatcher edits, run `008` down on a reset demo base (down restores the 007 CHECKs; precondition: no `auto`/`handoff` rows — guaranteed by reset); accepted WU5–WU14 surfaces, the WU14 mount and all prior data untouched by construction.
